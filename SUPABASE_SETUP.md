# Supabase Setup

Create these tables in the Supabase SQL editor before testing the forms.

```sql
create table if not exists public.waitlist_signups (
  id bigint generated by default as identity primary key,
  email text not null,
  source text not null default 'landing_page',
  created_at timestamptz not null default now()
);

create unique index if not exists waitlist_signups_email_key
  on public.waitlist_signups (lower(email));

create table if not exists public.beta_feedback (
  id bigint generated by default as identity primary key,
  email text not null,
  fitness_goal text,
  biggest_challenge text,
  most_interesting_feature text,
  would_pay text,
  created_at timestamptz not null default now()
);

create unique index if not exists beta_feedback_email_key
  on public.beta_feedback (lower(email));
```

The app uses `SUPABASE_SERVICE_ROLE_KEY` inside server route handlers only. Do not expose that key with a `NEXT_PUBLIC_` prefix.

## MailerLite Waitlist Number

Create a MailerLite custom field named `waitlist_position`. The waitlist API route sends the Supabase `waitlist_signups.id` value into that field for each new waitlist subscriber.

Use MailerLite's personalization tag for that field inside the waitlist automation email to show the user's waitlist number.

## MailerLite Unsubscribe Webhook

Create a MailerLite webhook for the `subscriber.unsubscribed` event and point it to:

```txt
https://your-domain.com/api/mailerlite/webhook
```

Copy the webhook `secret` from MailerLite into `.env.local`:

```txt
MAILERLITE_WEBHOOK_SECRET=your-mailerlite-webhook-secret
```

When a subscriber unsubscribes in MailerLite, this endpoint verifies the webhook signature and deletes that email from both `waitlist_signups` and `beta_feedback`.
